- Team (user, 2026-11-09): docs/TEAM.md - a coordinator (the session the user talks to) and six leads (bridge/fork, world and models, interaction/UI, VR, combat, QA/release), each in its own worktree and branch, owning its paths, with subagents from `.claude/agents/` (fork-dev, client-dev, reviewer, test-runner). Leads commit on their branches and report; the coordinator merges, tests and pushes.
- Contract changes go through the B lead; update TASKS.md + WORKLOG.md when a sub-block is done.
- VR-ready rules (PLAN.md block L): input only via E1's action map; UI works inside a `SubViewport` (no screen size, OS cursor or global mouse); no heavy main-thread work; camera rig separate from the player body.
- Releases (bridge for people without a compiler; `v0.1.0` Windows, `v0.2.0` Windows + Linux, 2026-11-05, `v0.3.0` 2026-11-07, prereleases on CDDA-Proj): build from committed, pushed sources (Windows `fp3d-cdda`; Linux `wsl_build.sh` with preset `fp3d-linux`, which maps source paths out with `-ffile-prefix-map`, then `objcopy --strip-debug`); scan both for personal strings (user name, email, tokens; only `D:\My Games\...` source paths may be in the DLL), check the `.so` exports only `fp3d_cdda_init`; `python -I tools/release/third_party_licenses.py <out>` for THIRD_PARTY_LICENSES.txt (add any new linked library); `gh release create vX.Y.Z --prerelease --target <full sha>` with the files + licences; notes give both SHA256 and both source commits; check GitHub's asset digests. Linux AppImage: commit and push first (BUILD_INFO records both commits), run `tools/build/appimage.sh`, test it in WSL (FUSE works there; WSLg renders with llvmpipe), upload the AppImage, its `.sha256` and its THIRD_PARTY_LICENSES.txt. Later: CI builds them (A3).
- Edits inside `cdda/` go under `cdda/src/fp3d/` or carry a `// FP3D:` / `# FP3D:` marker.
- Linux build from Windows: in WSL (Ubuntu-24.04) `bash tools/build/wsl_build.sh [targets]` from the checkout; it rsyncs to `~/cdda3d`, builds with one job per 2 GB RAM, copies the `.so` back. From Git Bash: `MSYS_NO_PATHCONV=1 WSL_UTF8=1 wsl.exe -d Ubuntu-24.04 -- bash <script>`. Linux Godot: `~/tools/godot-4.7.2/Godot_v4.7.2-stable_linux.x86_64`. After a bridge CMakeLists change, Windows needs `--preset fp3d-msvc --fresh` (Freetype link error otherwise).
- VR without a headset: SteamVR's null driver (`<Steam>\steamapps\common\SteamVR\drivers\null\resources\settings\default.vrsettings`: `enable` true, window 1280x720 at 100,100; original kept as `default.vrsettings.fp3d-orig`) and in `<Steam>\config\steamvr.vrsettings`: `steamvr` requireHmd false / forcedDriver null / activateMultipleDrivers true / enableHomeApp false, `power` pauseCompositorOnStandby false + turnOffScreensTimeout 86400, `dashboard` enableDashboard false (without these SteamVR goes to standby: the session never gets focus and nothing is drawn). SteamVR must be up before the game (the launchers do it). Quitting in VR goes through main.gd `_quit`: with SteamVR on Windows the engine's own teardown crashes (any graphics API), so it frees the scene and ends the process itself; not seen on Linux yet. VR frames can't be read back: `--screenshot` in VR renders the head's view with a plain camera. To undo: restore the `.fp3d-orig` file and remove those keys.
- Art coverage: `python -I tools/coverage/coverage.py --data cdda/data/json` (3 s).

## Key facts
- Client: run `D:\Tools\Godot\Godot_v4.7.2-stable_win64.exe --path client` (first person; V outside view; keys in the HUD; `-- --view=outside`, `--snapshot=<path>` loads another file, `--ids=<path>` other id tables; `--view-z=0 --no-roofs --camera=x,y,z,yaw,pitch --screenshot=<png>` for a picture). Tests: `Godot_v4.7.2-stable_win64_console.exe --headless --path client --import` once, then `--headless --path client --script res://tests/run_tests.gd` (also runs the E3 UI tests). The 363-submap mock builds in ~0.6 s, 735 k vertices with props (1058 furniture); the id tables JSON parses and validates in ~0.3 s.
- Client axes: 1 tile = 1 m, 1 z = 3 m, east = +X, south = +Z; Godot origin = bubble corner, rebased on shift. Walls fill their tile. Godot's JSON gives every number as a float.
- CDDA's sun azimuth (`env.sun_az_deg`) is measured from the south, positive toward the west (calendar.cpp). `t_soil` is solid earth (a wall), not a floor.
- CDDA: C++, JSON data (0.I: all items are type `ITEM`), licence CC-BY-SA 3.0, so this project must be too.
- Reality bubble 11×11 submaps of 12×12 tiles (132×132), z -10..+10 (`map_scale_constants.h`); 100 moves = 1 turn = 1 s.
- Game code is the OBJECT library `cataclysm-tiles-common`; tests link it with `SDL_MAIN_HANDLED` — so does fp3d-headless.
- `tests/test_main.cpp` `init_global_game_state()` is the reference for booting CDDA without a window.
- Built with SOUND and LOCALIZE off: vcpkg's SDL2_mixer config wants libxmp, which isn't installed. Game audio will come from Godot.
- `overmap_buffer.closest_city()` only searches generated overmaps: call `overmap_buffer.get()` first.
- CDDA's preset hard-codes `VCPKG_ROOT=C:/vcpkg`; our `CMakeUserPresets.json` (copy in tools/build/) overrides it.
- Data size: ~10.1k items, 1.1k monsters, 1.1k terrain, 659 furniture, 486 vehicle parts.
- 16 terrain registry entries already cover ~62 % of spawn-weighted terrain (73 % with looks_like).
- Test baseline, unmodified game code, seed 1: 11 failures. 5 are translation tests (LOCALIZE off). `limit_mod_size_bonus` fails even alone (a creature already stands on the spawn tile). It leaves a creature behind, which makes 4 `monsters_spawn_*` tests and `mission_goal_condition_test` fail in the full run; they pass alone.
- Delete `cdda/test_user_dir/` before each test run: tests write past games there, and a second run then fails `achievements_tracker` and `default_overmap_generation_has_non_mandatory_specials_at_origin`. After B2 with a clean dir: same 11 failures as baseline.
- Bridge facts: the main loop polls on a 125 ms timer even with animations off (hooked in `get_player_input`). `choose_direction`, `look_around` and `target_ui::run` (EDGE_SCROLL timeout) are replaced by one request each. `init_interface()` itself does SDL init, then options init+load (boot mirrors main). `game::start_game` is private: use `fp3d_game_access` (one friend line in game.h). Headless, ui_adaptor resize callbacks never run (`ui_manager::redraw` returns early), so what they set up must be set on the bridge path: `target_ui::fp3d_init_aim` sets the aim modes `init_window_and_input` would (without it the first gun shot crashed, `aim_mode` in an empty list; fixed 2026-11-08, sim test `shoot` checks). After a shot CDDA aims again (the aim activity re-enters `target_ui`) until cancelled.
- Never use CDDA's `init_crash_handlers()` in automated runs: it shows an SDL message box and hangs. On MSVC, signal handlers are per thread; fp3d-sim-test uses a vectored handler that prints the stack and exits 3.
- A CMake re-configure can fail on vcpkg's SDL2_ttf (`Freetype::Freetype` not found); `cmake --preset fp3d-msvc --fresh` fixes it (any CMakeLists change triggers it, e.g. a new file in `src/fp3d/`; `--fresh` means a full rebuild, ~15 min).
- Agent tooling: in Bash heredocs, `\n` inside Python strings reached C++ files as real newlines. Use the Edit tool for C string escapes. Python's `read_text`/`write_text` default to cp1252 here and `write_text` empties the file before failing on non-cp1252 text: use `read_bytes().decode("utf-8")` / `write_bytes`. It also turns LF into CRLF (harmless: `core.autocrlf` is on).
- `input_context::get_registered_actions()` / `is_action_registered()` exist only in Android builds.
- Real-time clock lives in `fp3d/bridge.cpp` (`pace_turn` in `do_turn` before the turn advances; the main-loop request is `timed`). Auto-pause hooks `game::mon_info_update` where a new hostile comes into view (reason "hostile spotted"), its own setting (`fp3d::set_auto_pause_hostiles`, `CddaSim.set_auto_pause`, on by default), no longer tied to safe mode.
- Random starts can put an NPC next to you or start in an unlit room: `fp3d-sim-test` kills NPCs and gives the avatar `DEBUG_NIGHTVISION`.
- Snapshot facts: a capture takes ~110 ms (RelWithDebInfo, full bubble); unchanged submaps are shared pointers. CDDA's vehicle caches are lazy (insides/fake parts refresh on `actualize`, e.g. a map shift), so vehicle roof flags can change on a shift: a real revision bump, not a bug. Fresh loads need `rebuild_vehicle_level_caches` + `build_map_cache` (boot.cpp does it).
- CDDA's safe mode refuses `pause` and moves while a hostile is in view (only a message, no turn passes). Since 2026-11-10 it is off in FP3D games, new and loaded (`boot_common` sets the SAFEMODE and AUTOSAFEMODE options false in memory); `safemode` (Shift+1) still toggles it, so scripted tests no longer send it.
- Id table facts: 1109 ter, 660 furn, 9913 items, 1155 monsters, 702 vehicle parts (0.I + dda). Wall symbols are CDDA line-drawing codes, exported as "". `trap::visibility` is private (not exported). Connect group names come from `fp3d_connect_group_names()` (FP3D addition in mapdata.cpp).
- Event facts: hooks cost one atomic load while events are disabled (CDDA's unit tests never enable them). Sounds are taken where CDDA works out what the player hears (`process_sound_markers`), not in `sounds::sound`. `fp3d-sim-test` sees ~350 turn_end events over its 8 goals: a client must drain often or lose them first.
- New fork worktree: `src/version.h` is generated empty (git describe fails in a git worktree), so `version.cpp` fails with "VERSION undeclared": write `// NOLINT(cata-header-guard)` + `#define VERSION "<sha>"` into it by hand (gitignored). Setting `FREETYPE_INCLUDE_DIR_*` by hand on a re-configure does not fix the Freetype error (the link then misses brotli/bz2): use `--fresh`.
- Agent tooling: `for( x : make_shared_thing()->member )` dangles (the temporary shared_ptr dies before the loop): keep the snapshot in a variable.
- Bridge facts: CDDA runs on its own 8 MB-stack thread in Godot's process; CDDA's hidden window uses SDL's software renderer whenever the bridge is active (no GPU device or driver threads for nothing). After a headless boot, call `fp3d::shutdown_world()` on the game thread before exit (the DLL and `fp3d-sim-test` do): CDDA's `atexit( SDL_Quit )` otherwise runs before its static tile caches free their textures (crash at exit), and in a DLL it runs inside DllMain and deadlocks on SDL's timer thread (Godot hung on exit). Stack dumps of a hung process (no debugger installed): `python -I tools/debug/stacks.py <pid>`. Boot ~30 s; `stop()` waits for boot to finish. Godot locks the DLL while running: close it before building. Snapshot JSON for 3 levels is ~0.9 MB.
- Load facts: `boot_saved_game` = main menu's load (`world_generator->init()`, `g->setup()`, `build_id_tables`, `game::load`); it never deletes. After a load `new_game` is true, so the first `do_turn` doesn't advance the turn: the first request has the saved turn. Save files are `#` + CDDA base64 (alphabet ends `+ -`) + `.sav` (`.sav.zzip` if compressed); a name starting with `#` is stored raw, so the bridge refuses those. The bridge lists folders itself (no CDDA globals) and only loads names its own listing gives.
- Id tables: 108 items have colour `c_unset`; `color_manager::get_name` raises a debug message for those (a popup outside test mode), so the tables use their own colour map.
- Request UI (E3): `RequestUI.show_request(req)` -> `answered(answer)` -> `LiveSession.answer()`. Keys reach it in `_input`, before main.gd's `_unhandled_input`; keys a widget doesn't use fall through (WASD flies). Directions and the target cursor are camera-relative through `direction_mapper`. RAW_KEY reads and timed (main-loop) requests never show: main.gd answers / skips them. Godot 4.7's Range doesn't emit `value_changed` when a script sets `value`: tests emit the signal themselves. Aiming: AimController.handle_event runs before look_at in `_unhandled_input`; LMB (`look_at`) and F (`cdda_fire`) fire only while a target request shows, because fp_tests forbid two actions sharing a default key.
- Planned scale: 1 tile = 1 m, 1 z-level = 3 m, 4×4 sub-tiles per tile.
- Client terrain rules (`terrain_catalog.gd`): kinds come from flags in a fixed order, then the looks_like chain (never structural kinds: monkey bars look like a ladder). Roofs = the `roof` of an INDOORS/WALL/WINDOW/DOOR terrain that isn't ground (t_soil's roof is t_dirt); treetops = the `roof` of a TREE. Colour: registry material, else the muted CDDA colour (`CddaPalette`: cyan reads as metal/glass).
- Registry field `placeholder` (procedural prop shape) added to the schema; coverage (0.I): furniture 65 % exact, 76 % with looks_like, the rest hit `generic_furniture_*`.
